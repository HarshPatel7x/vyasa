- [x] **CI workflow polish — independent validation steps + checkout v5 (2026-06-01).** Two trivial tweaks to `.github/workflows/pr-format-check.yml`, bundled on one branch (shipped on the fly). (1) Added `if: ${{ !cancelled() }}` to each of the three validation steps ("Validate PR title", "Validate PR body", "Validate commit messages") so all three targets are checked and reported in a single run — previously the steps ran sequentially with no condition, so a failed title check aborted the body and commit-message checks and the author saw only the first error per round trip. Chose `!cancelled()` over `always()` deliberately: `always()` would run even on a cancelled run, defeating the workflow's existing `concurrency: cancel-in-progress`; `!cancelled()` runs on failure-of-prior-steps but still respects cancellation. Checkout deliberately left unconditional — the validation steps depend on it. (2) Bumped `actions/checkout@v4` → `@v5` to clear the Node-20 deprecation warning. No other workflow changes (`fetch-depth: 0`, job env, permissions, concurrency, the three steps' env vars all unchanged). This is a tweak to the existing CI enforcement, not a structural change — no `README.md` / D-entry. Verified locally: YAML re-parses (`ruby -ryaml`, python yaml absent here); `!cancelled()` present on exactly the three validation steps and not on Checkout; no `@v4` remains. No live Actions run possible locally (`actionlint`/`act` not installed) — live run watched on the introducing PR. Branch `workitem/ci-workflow-polish`. Plan: [`plans/ci-workflow-polish.md`](plans/ci-workflow-polish.md).

Three named steps (title / body / commits) so a red ✗ names the failing target; read-only token; plain `pull_request` (never `pull_request_target`); title/body via env vars (no shell injection); locale pinned `C.UTF-8`; `fetch-depth: 0`. - [x] **Diff-verification hook to catch hallucinated edits (2026-06-01).** Shipped a PreToolUse + PostToolUse hook pair wired in project-scope `.claude/settings.json` (matcher `Edit|Write|MultiEdit`): `hooks/snapshot-before-edit.sh` snapshots a file's bytes *before* an edit, and `hooks/verify-diff.sh` diffs that snapshot against the post-edit bytes to surface the exact **per-edit** delta — user-facing via `systemMessage`, plus a factual neutral note injected into the model's context (`additionalContext`) when a reported-successful edit changed nothing on disk. Snapshot-pair design (not `git diff`, which shows cumulative-since-commit, not this edit) was forced by a blocking flaw caught in plan review; it also covers untracked/git-ignored/new files since git is never involved. Both hooks fail-open (never block an edit), no-loop (raw-shell snapshot writes, never Edit/Write tools), pair deterministically by `tool_use_id` (counter fallback), and are bounded (5 MB oversize guard, output capped well under the ~10K-char hook limit, snapshots deleted after use). `NotebookEdit` excluded (`notebook_path` + noisy JSON cell-diffs; no notebooks in repo). Hook *logic* verified this session by 22 hand-made-JSON cases (modify, new, no-op, git-ignored, non-repo cwd, two-edits-one-turn, orphan-silent, oversize, malformed-JSON, counter-fallback — all pass); the genuine live trigger needs a fresh session because Claude Code snapshots hook config at startup and does not reliably hot-reload `settings.json` (confirmed empirically). Branch `workitem/diff-verification-hook`. Plan: `plans/diff-verification-hook.md`. See `D19 — Project-scope Claude Code Pre/PostToolUse hooks for edit verification`.
