- [x] **Diff-verification hook to catch hallucinated edits (2026-06-01).** Shipped a PreToolUse + PostToolUse hook pair wired in project-scope `.claude/settings.json` (matcher `Edit|Write|MultiEdit`): `hooks/snapshot-before-edit.sh` snapshots a file's bytes *before* an edit, and `hooks/verify-diff.sh` diffs that snapshot against the post-edit bytes to surface the exact **per-edit** delta — user-facing via `systemMessage`, plus a factual neutral note injected into the model's context (`additionalContext`) when a reported-successful edit changed nothing on disk. Snapshot-pair design (not `git diff`, which shows cumulative-since-commit, not this edit) was forced by a blocking flaw caught in plan review; it also covers untracked/git-ignored/new files since git is never involved. Both hooks fail-open (never block an edit), no-loop (raw-shell snapshot writes, never Edit/Write tools), pair deterministically by `tool_use_id` (counter fallback), and are bounded (5 MB oversize guard, output capped well under the ~10K-char hook limit, snapshots deleted after use). `NotebookEdit` excluded (`notebook_path` + noisy JSON cell-diffs; no notebooks in repo). Hook *logic* verified this session by 22 hand-made-JSON cases (modify, new, no-op, git-ignored, non-repo cwd, two-edits-one-turn, orphan-silent, oversize, malformed-JSON, counter-fallback — all pass); the genuine live trigger needs a fresh session because Claude Code snapshots hook config at startup and does not reliably hot-reload `settings.json` (confirmed empirically). Branch `workitem/diff-verification-hook`. Plan: `plans/diff-verification-hook.md`. See `D19 — Project-scope Claude Code Pre/PostToolUse hooks for edit verification`.
